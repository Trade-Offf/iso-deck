# 镜头：什么时候推近，推多少

观众的眼睛跟着镜头走。镜头推到哪里，观众就看哪里。推得太多、太频繁，观众会晕，也会丢掉“它在整体里哪个位置”的感觉。

## 规则

1. **每页开头是全景**。翻页时先让观众看到全图和这一页的变化。
2. **只在要指着某一块讲的时候推近**。一页里逐块讲 2–4 块，就写成 beats。
3. **推 1.2–1.35 倍**（`zoom` 默认 1.3）。少于 1.1 看不出变化，超过 1.5 就丢了上下文。
4. **切换区域时先回全景**。从左边的“入口”讲到右边的“异步”，中间那一拍不要直接横移，横移会晕。实际做法是相邻两拍的 focus 不要隔得太远；隔得远时中间插一拍全景。
5. **停留 1.5–3 秒再说话**。镜头动完、观众找到位置，再开始讲。录视频时 `playbook` 会在每次翻页后留 1.4 秒过渡。
6. **每页最后一拍回到全景**。不带 `focus` 的一拍就是回到全景，`validate` 会提醒漏写的情况。

## 什么时候不需要 beats

- 一页只有一个变化：翻页本身的动画已经把视线引过去了。
- 结果页、柱状图页：东西少，不用推。
- 封面。

## 手动镜头 `camera`

`scene.camera: { at: [x, y], zoom }` 会跳过自动取景。适合：

- 这一页只关心图的一部分（比如“方案”页只看平台内部），用 `at` 对准那一块，`zoom` 1.2–1.4。
- split 封面，把图推到右边。

用了手动镜头后，图的另一部分可能会被裁掉，`shoot` 会报“超出画面”。如果那一部分本来就不是这一页要讲的，可以接受。

## 节拍写法

```js
beats: [
  { say: '先看入口：请求先到网关。', focus: ['users', 'gw'] },
  { say: '再看核心：订单服务协调库存和支付。', focus: ['order', 'stock', 'pay'], zoom: 1.2 },
  { say: '这就是全景。' },
]
```

- `focus` 选 1–4 个相邻的实体。选得越多，推得越远；隔得很远的实体放一起，等于没推。
- 给这一拍配 `card`，信息卡会跟着换；不配就不显示，画面更干净。
- `say` 一句话就够，它就是这一拍的口播。
