# 数字台账

汇报被追问时，最难堪的是答不出“这个数怎么来的”。所以每个数字只写一次，旁边写上出处。

## 写法

```js
facts: {
  cost_old: { value: '¥1.2', source: '翻译组 9 月账单，按实际用量折算，每百条' },
  cost_new: { value: '¥0.1', source: '10 月 8 日实测 100 条，按量计费' },
  cost_ratio: { value: '12 倍', source: '计算：cost_old ÷ cost_new' },
},
```

页面里写 `{cost_old}`，所有可见文字都支持：标题、正文、信息卡、标签、连线文字、封面、提词、节拍的 `say`。改数字只改台账一处。

- `value` 带上单位（`'87 分'`、`'0.5–1 天'`），页面里就不用再写单位。
- `source` 写到别人能复核的程度：谁、什么时间、什么口径、样本多大。
- 推算出来的数字也进台账，`source` 写算式。
- 示例或估算的数字，`source` 开头写“示例数据”或“估算”。

## validate 会查什么

| 级别 | 情况 |
| --- | --- |
| ✗ | 台账项不是 `{ value, source }`，或 `source` 为空 |
| ✗ | 页面里的 `{key}` 在台账里找不到 |
| ! | 有台账，但页面上还有硬写的数字（金额、百分比、倍数、天、条、分……） |
| ! | 台账里有，但没有一页用到 |
| ! | 整份 deck 没有台账，但页面上有数字 |

有些数字不是“数据”，比如“第 ③④ 步”“三个问题”，不会被报出来。真被误报时，可以换成中文数字，或者也放进台账。

## 比例悬殊时别按比例画

柱状图的高度、信息卡对比条的长度，会被最大的那个值决定。¥292、¥14、¥1.1 放在一起，后两根几乎看不见，整个坐标系就“崩了”。

- 相差超过 10 倍：只画两根量级接近的，悬殊的那个用文字对照（“作为对照：旗舰模型每百条约 {cost_flagship}”）。
- `validate` 发现 3 个以上数值、其中至少 2 个不到最大值的 1/12 时，会提醒。
- 分数类（满分 100）给对比条写 `max: 100`，不要按本组最大值归一。

## 对外分享前

- 真实业务数字换成示例值，`source` 写明“示例数据”。
- 改了数值以后，检查由它推算出来的结论（倍数、“降一个数量级”）还成不成立。
- 柱子高度（`h`）和对比条 `value` 是画面参数，不走台账，要同步改。
