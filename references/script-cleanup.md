# 整理稿子

用户给的往往是口播录音转写、会议记录或零散提纲。先把它整理成“一页一件事”的稿子，再动手画图。

## 清理

**删掉**：

- 重复说的话（“就是说，就是说”），只留最后、最完整的一遍。
- 起了个头又改口的半句话。
- 口误和更正：只留更正后的说法。
- 语气词和填充词：嗯、啊、那个、然后呢、对吧。
- 和主线无关的插话。

**一定保留**：

- 每一个数字，以及它的单位、口径（“按套餐折算”“抽样 30 条”）。
- 条件和例外（“只翻空着的格子”“失败重试 1 次，再失败留空”）。
- 结论和判断（“不追求最好，追求投入产出比”）。
- 专有名词：系统名、角色名。对外分享时再统一脱敏。

拿不准一句话该不该删，就保留。删掉的信息找不回来，多出来的只占地方。

## 切页

1. 按“听众此刻在想什么问题”切段。每段回答一个问题，就是一页。
2. 每页写一个 `short`（2–4 个字，放步骤条）和一个 `title`（一句话结论，不是话题）。
   - 好：`成本：每百条 {cost_old} → {cost_new}`
   - 不好：`成本分析`
3. 原话整理后放 `notes`，一句一个数组元素。演讲者按 `N` 看。
4. 讲稿区 `body` 只放 1–3 条要点，比口播短一半以上。观众是在听，不是在读。
5. 一页里要指着画面逐块讲的，拆成 `beats`，每拍的 `say` 就是这一句口播。

## 检查

- 每页 `notes` 能不能在 30–60 秒讲完？超了就拆。
- 把所有 `title` 连起来读，像不像一篇完整的摘要？像就说明主线对了。
- 稿子里出现的每个数字，都进了 `deck.facts` 吗？（`validate` 会帮你找漏掉的。）
- 有没有只在画面里出现、口播里没提的东西？要么删掉，要么补一句。
